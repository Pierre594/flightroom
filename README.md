# Flightroom — drone flight viewer

A local browser application for visualizing synchronized drone flights using GLB models and CSV files. The application starts with the example model `models/example/Drone1.glb` and example flight `data/example/Drone1.csv`. Your own files in `models/` and `data/` are kept separately.

## Run locally

Install Node.js 20.19+ or 22.12+, then run:

```sh
npm install
npm run dev
```

Open the local URL printed in the terminal (normally http://127.0.0.1:5173/). Keep the terminal running. Use a modern desktop browser with WebGL enabled. Files stay on your computer; no server-side upload is involved. Internet is needed for the initial dependency installation; the optional interface fonts are loaded from Google Fonts and fall back to system fonts if unavailable.

To build a production version, run `npm run build`; `npm run preview` serves the build locally. Run `npm test` to check the flight data processing.

Both workspaces save named JSON projects in the application's `projects/` directory. Enter a **Project name** and choose **Save project**; saving the same name replaces the existing file, even if it came from the other workspace. Choose a project from **Saved projects** and click **Open saved** to reopen it. **Import JSON** opens older downloaded project files. Local project storage requires the application server (`npm run dev` or `npm run preview`); the folder is created automatically.

## Use

- Drag to orbit, scroll to zoom, and right-drag to pan. The editable **Camera angles** fields set the azimuth and elevation of the camera around its current target in world coordinates; distance and zoom stay unchanged. Use **Top**, **Side**, and **Back** on the viewport to snap the camera around its current target without changing its distance. Top looks down from +Z, Side looks from +Y, and Back looks from −X in flight coordinates. Top, Side, and Back preserve the current projection; the default is perspective. Selecting one pauses playback; add or update a keyframe to save it. To animate the camera, scrub to a timeline position, adjust the view, and click **Add view at current time**. Scrub to another time, adjust the view, and add another keyframe. Scrubbing or manually adjusting the camera pauses playback so your view changes are preserved while you set a keyframe. Click a keyframe marker or time to jump to it; drag its timeline marker to change its time while keeping its saved view. Two keyframes cannot occupy the same time. Adjust the view and click **Update view at current time** to replace it. Use × to delete a keyframe.
- With no keyframes, the current camera view stays fixed. With one, its view is held throughout the flight. With multiple keyframes, the first and last views are held outside their times; between them, camera target, distance and zoom use cubic Bézier ease-in/ease-out, while the viewing direction follows a spherical arc. Projection mode is saved per keyframe; when consecutive keyframes use different projections, the projection switches at the next keyframe. The same camera animation plays while scrubbing, during playback and during video export.
- **Follow camera** attaches the current view to a selected flight's position and CSV yaw. Selecting a flight aims the camera at it; left-drag orbits around that flight, right-drag pans, and scroll zooms. Starting another orbit recenters the target on the flight. The camera and its look-at target maintain their offsets in the flight's heading frame; X and Y are horizontal, Z is up, and X is the zero-yaw direction. Roll and pitch do not tilt the horizon. The X/Y/Z fields adjust the camera position offset in meters. Follow works during scrubbing, playback and export, and is saved with the project. Camera keyframes are temporarily inactive while following; turn follow off to use them again. Removing the followed flight turns follow off.
- Press play or drag the timeline to inspect the flights. Use **Fit view** to reset the camera to show the flight paths.
- **Add CSV files** adds one drone per file. Remove an existing flight with its × button. **Restore example flight** replaces the flight list with the included example.
- Replace the default model using the arrow beside its name. Each newly loaded CSV uses that default; use **Choose GLB** under a flight to assign a different model to that drone, or **Use default** to switch it back. Set each flight’s **Scale** independently; **Overall scale** multiplies all flight scales. The GLB's own origin is used as the position reference; model orientation and pivot calibration are not yet configurable. The viewer preserves GLB opacity and corrects matching flat color factors from Onshape exports for display. The included model contains only opaque materials; restoring actual transparency requires a model exported with transparency information.
- The camera graph plots azimuth, elevation, distance to the target and view height over time. View height is the visible vertical span at the target and reflects zoom in both projections. Azimuth is measured in the flight XY plane from +X toward +Y, using the direction from the target to the camera; elevation is measured above that plane. Azimuth is unwrapped to keep the plotted curve continuous. The distance curve shows camera distance to the target. In perspective the mouse wheel changes that distance; in orthographic mode it changes magnification instead. The curves show saved keyframes or the follow view when following; the numbers show the current view, including unsaved camera adjustments. Click the graph to seek.
- **Show axis labels** displays axis names and one-meter tick labels on the scene axes (the horizontal axes run from −15 m to +15 m and the vertical axis from 0 m to 3 m). The labels also appear in exports and are hidden when the axes are hidden. Use **Axis label size** to adjust their font size; the setting is saved with the project.
- The camera position readout above the viewport uses flight coordinates in meters: X and Y horizontal, Z up. It updates while orbiting, zooming, panning, scrubbing, and playing. Camera keyframes and saved projects retain camera position and target.
- Under **Cable connections**, select two different drones and add a cable. Each cable's length (default 1 m) and diameter (default 12 mm) can be edited independently; multiple cables are supported. Cables and their drone assignments are saved in the project and included in exports. Removing a drone removes its cables; restoring the sample flights resets the connections.
- Each cable connects the two CSV position points (the model origins), using a gravity-driven catenary with the specified length. This is a static visual approximation at each timestamp, without dynamics, wind, collision or attachment offsets. If the length is shorter than the drones' separation, the viewer displays a straight red cable and warns by how much it is too short. A slack cable may extend below the floor and be obscured; the floor does not affect its shape.
- **Show skybox** enables a surrounding sky that rotates with the camera but does not move as the camera pans. Select **Sample sky** for the included generated panorama, **360° panorama** for a 2:1 equirectangular PNG, JPEG, or WebP, or **6 cube faces** for six square images of identical size. Name the faces `px`, `nx`, `py`, `ny`, `pz`, and `nz` with their image extensions; they use the standard Three.js cube-map convention (Y up). Flight coordinates map to Three.js as `(X, Z, -Y)`. **Show floor** controls the gray ground; shadows are visible when the floor is shown. Skybox images and visibility settings are saved in the project and included in video exports. The skybox is visual only; it does not change the fixed lighting.
- Older projects with a flat background still open, with that image mapped as a panorama. For a seamless sky, replace it with a proper 360° panorama or matching cube faces.
- **3D text** adds a camera-facing label with an adjustable size multiplier (0.1×–20×; 1× is the default). Choose **Fixed world position** and enter `(X, Y, Z)` in meters, or choose a CSV flight under **Attached to** to follow that drone. For attached text, `(X, Y, Z)` is an offset in world axes from the flight position; it does not rotate with the drone. Set its visible interval in seconds from the start of the combined timeline; leaving the end blank uses the flight end. Both interval endpoints are included. Labels can be edited or removed and are saved with the project. If an attached flight is removed, the text is retained but hidden until reassigned. **Show 3D text** controls visibility.
- **Show timestamp** displays elapsed timeline time in the bottom-right corner of the 3D view and exported video. The timestamp and 3D text switches are saved with the project.
- **Show shadows** controls ground shadows from a fixed directional light. The shadow follows each drone in playback and exported video; the setting is saved with the project.
- **Show model edges** adds dark outlines along mesh boundaries and sharp edges, in both the preview and the exported video. The setting is saved with the project.
- **Animate propellers** rotates the four propellers of the supplied Gemfan/iFlight drone model around their motor shafts. Set the visual speed in RPM; the animation is tied to timeline time and appears in video exports. **Propeller motion blur** adds a simulated trail and can be switched off. It is an illustration, not a measurement from the CSV, and its direction and speed are fixed rather than derived from flight data. Other GLB models are unaffected unless they use the same identifiable parts. The settings and speed are saved in the project. Very high RPM may appear to slow down or reverse in 30 fps exports due to frame-rate aliasing.
- **Save project** downloads a JSON file containing all assigned GLB models, flight samples, individual scales, cable connections, timed 3D text, the selected skybox images, scene settings, current camera view, and camera keyframes. **Open project** restores them. Project files can be large because the models are embedded.
- Use **Frame format** above the 3D view to choose 16:9 or 4:3. Drag a corner of the preview to resize it while keeping the selected aspect ratio; focused corner handles can also be adjusted with the arrow keys. The preview size does not change the exported video's resolution. The frame format is saved with the project.
- **Export video** offers MP4 (H.264) and WebM, at 1080p, 720p or 540p, and 30, 24 or 15 frames per second. At 1080p, 16:9 exports are 1920 × 1080 and 4:3 exports are 1440 × 1080. MP4 normally uses the locally installed FFmpeg when running through `npm run dev` or `npm run preview`; FFmpeg must be available on the server PATH. Otherwise it uses browser encoding when available. Frame-by-frame export may take longer than the flight but avoids shortening it, shows progress, and can be cancelled. If only real-time recording is available, duration depends on rendering performance. When complete, the video normally downloads automatically and a download link remains available near the export button; the local FFmpeg link expires after one hour. Video includes the 3D viewport and in-frame text, not surrounding controls. The local encoder uses a temporary file; browser-encoded videos are assembled in memory, so long exports may use substantial memory. Restart the app after installing FFmpeg or updating the server configuration.
- Rigid, opaque meshes from compatible Onshape models are automatically grouped by material and moving part to reduce drawing overhead. Transparent and animated parts remain separate; other model formats are left unchanged.
- **MP4 speed** selects the local FFmpeg input format: **Fast** uses high-quality JPEG frames and a faster H.264 preset; **High quality** uses PNG frames and the previous H.264 preset. JPEG adds some image loss and the faster preset can produce larger files. The option applies to the local FFmpeg path; browser fallback uses its own encoder. Choosing 540p and/or 15 fps reduces the amount of work substantially, at the cost of detail and motion smoothness. Turning off shadows or propeller blur can also reduce rendering time. Export time depends on the scene and computer.

## CSV format and assumptions

Each CSV needs this comma-separated header:

```text
time,position_x,position_y,position_z,roll_rad,pitch_rad,yaw_rad
```

Times are seconds on a shared clock and must be strictly increasing within each file. Both tabs accept the legacy `time_s` header as well as `time`; older flight CSVs using `x_m`, `y_m`, and `z_m` also remain readable. Use only one name per coordinate. Position is in meters, and angles are in radians by default. Choose **Degrees** in the CSV angle unit selector before adding a file that actually contains degrees. The selected unit applies to all imported angle values regardless of whether their columns are named `_rad`, `_deg`, or just `roll`, `pitch`, `yaw`. Existing saved projects with `_deg` angle data are converted from degrees automatically; projects saved by the current version store normalized radians. For an existing flight, use its **Angles interpreted as** selector to change how the original values are interpreted without removing the flight. For example, switch it to Radians if an older project imported radian values under `_deg` headers. The current convention is a right-handed world frame with Z up: roll about X, pitch about Y, yaw about Z, applied as `Rz(yaw) * Ry(pitch) * Rx(roll)`. Three.js uses Y up internally, so the viewer converts flight coordinates `(x, y, z)` to scene coordinates `(x, z, -y)` and converts rotation consistently. The imported GLB is assumed to be correctly oriented at zero flight attitude. Confirm these conventions, the GLB's forward direction, and its origin before interpreting real flight data.

Samples are linearly interpolated in position; orientation uses quaternion spherical interpolation. Outside a particular drone's recorded interval its first or last pose is held. If sample intervals contain rotations of more than π radians (180 degrees), the shortest quaternion interpolation may not reflect the actual maneuver. The floor is at flight Z = 0. The demo sets each model's origin at ground level at the start; parts of the model may be below the floor depending on its origin.

## Equations in labels

Use inline LaTeX-style math between dollar signs in chart titles, subplot titles, axis labels, legends, timed chart text and floating 3D text. Mix ordinary text and math, for example `Tension $T_{\mathrm{est},1}$ (N)`, `$\alpha$ (rad)`, or `$\frac{a}{b}$`. Common subscripts, superscripts, Greek letters, fractions and mathematical symbols are supported. The same labels appear in the preview and video exports, and are saved in projects. Invalid or unmatched expressions are displayed as typed. Math rendering is bundled locally.

## Data animation

Select **Data animation** at the top of the app to create a scrolling chart with its own playback and export. Each subplot lists its CSV sources; choose **Replace CSV** to load an updated file. Matching column names retain their curve settings and subplot assignments, new columns are added to the selected subplot, and columns absent from the new file are removed. Replacing a source updates its curves in every subplot and keeps timestamp annotations linked to it. Under **Figure & subplots**, choose **Add CSV files** inside the subplot where the curves should appear. Each file's first column is `time` in seconds and its remaining columns are numeric series, for example:

```csv
time,altitude,velocity
0,0,0
1,0.5,0.5
2,1,0.5
```

Times must increase strictly within each file. Empty data cells produce gaps in the curve; other non-numeric values are rejected. Files share a time origin, but the data and 3D tabs have independent timelines and do not automatically synchronize. Each column becomes a series under its chosen subplot, with its own visibility, legend text, color, line style and width. Use **Collapse data series** to hide those controls, or **Move to subplot** to reassign an existing series.

Under **Figure & subplots**, the layout map shows the current arrangement; click a cell to find its settings. Use **Plot beside** or **Plot below** on a subplot to add the next plot in that direction. Each subplot has its own optional title, axis labels, vertical scale and legend settings. Width and height controls are percentages of the available figure area. When the combined sizes along the arrangement direction exceed 100%, they are scaled proportionally to fit. Removing a plot moves its series and text to the first remaining plot.

For one plot above two side-by-side plots, choose **Plot below** on the first plot, then **Plot beside** on the new one. The arrangement switches to grouped rows or columns automatically. The arrows along the main direction move the whole row or column; the other arrows reorder plots within that group. The row or column numbers remain available for precise grouping.

Figure width and height are the exact video dimensions in pixels, including for transparent WebM. They must be even, between 320×240 and 3840×3840, and no larger than 8.3 megapixels. The preview uses the same proportions and layout as the exported frame. Frame format and resolution presets remain available.

Under **Plot annotations**, add text or a vertical line to a subplot. For a fixed annotation, X and text Y positions are percentages from the upper-left of the plotting area. Choose left, center or right text alignment to decide which part of the label sits at its X position; this also applies to time-following and attached text. For an annotation that moves with the data, choose **Follow a CSV timestamp**, select an imported CSV, enter a timestamp within its range and optionally add a positive or negative time offset. Timestamp-following text enters from the right edge when its timestamp plus offset enters the displayed window, which can be before playback reaches that time. It then moves with the data until its last letters leave the left edge. Vertical lines appear when playback reaches their timestamp. Alternatively, choose **Fixed, then attach at a CSV timestamp** and set an X position. The annotation stays there until the timestamp plus offset, then attaches to the time axis at its current location and moves with it, without jumping. Optionally enter **Detach at X position (%)** to stop the element when it reaches that horizontal position, where 0% is the left edge and 100% is the right edge. If it first appears past that position, it stays at its initial position without jumping. Leave the field blank to keep following the data. For either time-following mode, you can also set **Reattach at timestamp**: once the annotation has stopped at its detach position, it remains there until that timeline timestamp and then follows the time axis again from the same position. Choose a reattach time after the stop is reached; changing the window settings can change when the stop is reached. The position is calculated consistently when seeking and exporting. Appearance and disappearance limits still apply after detaching. If the source CSV's series are all removed, anchored annotations are hidden until reassigned; fixed-then-attach annotations remain visible in their fixed phase. Appearance and disappearance limits are optional extra visibility bounds, in seconds. Text size and line color, style and width can be adjusted. Annotations can be edited or removed and are saved in the graph project.

Set the window duration and cursor threshold to control when the graph begins scrolling. Near the end, the window stops with the final time at its right edge; playback and the signal continue to that edge. Each visible curve has a colored marker at its latest visible point; use **Show line-end markers** to hide or show them. When the entire dataset is shorter than the selected window, the whole dataset fits in a fixed window. Each subplot's automatic vertical limits follow the displayed portions of its visible series, including interpolated values at the window edges. **Scale step** rounds those limits outward to fixed levels (1 by default), and the app smooths transitions between levels. The scale is kept wide enough for the displayed data and its margin, including during rapid changes; the original curves are not filtered. The transition profile is calculated from the full timeline so seeking and video export match playback. **Margin per side** adds a percentage above and below the data (10% by default); a flat signal is given a non-zero reference range. Choose **Manual limits** to set fixed minimum and maximum values. Under **Chart labels**, adjust the main title's size and alignment and use the shared slider to change all axis and legend labels. Subplot title sizes are adjustable in each subplot. Each subplot has a legend for its own visible series; choose a corner or **Above plot · horizontal** in that subplot's **Legend** settings. An inside legend can also be dragged within its plot. Moving the shared label slider resets all legend sizes to its value; each legend can also be sized separately.

Choose a figure background color and opacity in **Background**. Each subplot's **Plot background** setting can instead use a custom color within its axes; the figure opacity applies to both the figure and plot backgrounds. The checkerboard in the preview indicates transparency. Select **ProRes 4444 with alpha (.mov)** for a transparent ProRes MOV; this requires the local export server and FFmpeg with the `prores_ks` encoder. Alternatively, choose **WebM with alpha**; local export requires FFmpeg with VP9 support, or a browser that supports transparent VP9 encoding. MP4 and regular WebM are flattened over white. **Export data video** exports the chart alone; the 3D tab exports its own video separately. **Save graph project** and **Open graph project** preserve the imported data and chart settings in a separate JSON file.
